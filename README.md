# Карта полигона «Садовка»

Статический сайт: HTML, CSS и JS без сборки. Размещается на GitHub Pages, но работает на любом хостинге, который умеет отдавать файлы.

```
index.html            страница
css/style.css         оформление
js/config.js          ← НАСТРОЙКИ (название полигона, верхняя сцена: время начала, галереи, параллакс)
img/hero/             картинки верхней сцены (лес, бойцы, машина, фото галерей)
js/store.js           чтение и запись данных (JSON или Supabase)
js/app.js             карта, панели, админка
data/games.json       игры и точки — этот файл вы обновляете после каждой игры
data/demo/            картинки для тестовых игр (можно удалить вместе с тестовыми играми)
tiles/                подложка, нарезанная на квадраты 512×512 (≈530 файлов, 9 МБ)
vendor/leaflet/       библиотека карт (лежит внутри сайта, чтобы не зависеть от чужих CDN)
supabase/schema.sql   запасной вариант: онлайн-база вместо файла (сейчас не используется)
tools/make_tiles.py   скрипт нарезки подложки
```

## Как посмотреть у себя на компьютере

Если открыть `index.html` двойным щелчком, сайт работать не будет: браузер запрещает страницам с диска читать соседние файлы. Нужен маленький локальный сервер:

1. Установите Python с python.org.
2. В папке сайта нажмите в адресной строке Проводника, введите `cmd` и нажмите Enter.
3. Выполните `python -m http.server 8000`.
4. Откройте в браузере `http://localhost:8000`.

## Публикация на GitHub Pages

GitHub Pages бесплатен, но репозиторий должен быть **публичным**. Адрес сайта будет `https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/`.

Через сайт github.com за один раз можно загрузить не больше 100 файлов, а в сайте их около 540 (в основном квадраты карты в `tiles/`). Поэтому первую заливку делайте через бесплатную программу **GitHub Desktop**. Дальнейшие обновления игр — это один файл, его удобно менять прямо в браузере.

### 1. Первая публикация (один раз)
1. Зарегистрируйтесь на github.com. Сразу включите двухфакторный вход: *Settings → Password and authentication*.
2. Установите GitHub Desktop (desktop.github.com) и войдите в нём в свой аккаунт.
3. В GitHub Desktop выберите **File → New repository**:
   - *Name:* `sadovka` (имя войдёт в адрес сайта);
   - *Local path:* любая папка, например `Документы\GitHub`;
   - нажмите **Create repository**.
4. Нажмите **Show in Explorer** и скопируйте в открывшуюся папку **содержимое** распакованного архива: `index.html`, `css`, `js`, `data`, `tiles`, `vendor` и остальное. Важно, чтобы `index.html` лежал прямо в этой папке, а не во вложенной.
5. Вернитесь в GitHub Desktop. Слева появится список файлов. Внизу впишите *Summary* (например «Карта полигона») и нажмите **Commit to main**.
6. Нажмите **Publish repository**, **снимите** галочку *Keep this code private* и ещё раз нажмите **Publish repository**.
7. На github.com откройте репозиторий, затем **Settings → Pages**. В блоке *Build and deployment* выберите *Source: Deploy from a branch*, *Branch: `main`*, папку `/ (root)` и нажмите **Save**.
8. Через 1–2 минуты вверху этой страницы появится ссылка на сайт.

Исходные куски карты (`images/*.gif`, 230 МБ) в репозиторий класть не нужно: сайту хватает папки `tiles/`.

### 2. Как обновлять игры
1. На опубликованном сайте нажмите на замок справа вверху и выберите «Включить».
2. Правьте игры и точки. Пока файл не загружен на GitHub, изменения видны только вам и хранятся в этом браузере.
3. Нажмите «Скачать games.json».
4. На github.com откройте в репозитории папку `data`, нажмите **Add file → Upload files** и перетащите скачанный `games.json`. GitHub заменит старый файл.
5. Нажмите **Commit changes**. Через 1–2 минуты обновления увидят все.

Можно и через GitHub Desktop: положите новый `games.json` в папку `data` на компьютере, затем нажмите **Commit to main** и **Push origin**. Так же обновляются любые другие файлы, например новая подложка.

Проверить, что публикация закончилась, можно на вкладке **Actions** в репозитории: зелёная галочка означает, что сайт обновлён.

### Свой домен (потом)
Купите домен у любого регистратора. В **Settings → Pages → Custom domain** впишите его и нажмите **Save**, а у регистратора добавьте DNS-записи по подсказке GitHub (для домена вида `map.example.ru` это CNAME на `ВАШ_ЛОГИН.github.io`). Когда домен заработает, отметьте **Enforce HTTPS**.

## Насколько надёжна защита админки

Сайт на GitHub Pages вообще не умеет ничего записывать. Режим редактирования меняет данные только в браузере того, кто его включил, и никто, кроме него, этих изменений не увидит. Опубликовать изменения может только тот, у кого есть доступ к вашему аккаунту GitHub.

Поэтому защита держится на аккаунте GitHub: сложный пароль и включённый двухфакторный вход. Пароль «внутри» самого сайта я намеренно не делал: такой пароль проверяется в браузере и обходится за минуту.

Кнопка с замком видна всем, но посетителю она ничего не даёт.

## Фото из Google Drive
1. В Drive откройте у файла **Настройки доступа** и выберите «Все, у кого есть ссылка».
2. Скопируйте ссылку вида `https://drive.google.com/file/d/…/view` и вставьте её в поле «Фото» (по одной ссылке на строку). Подпись добавляется через `|`.
3. Сайт сам превратит ссылку в картинку. Ссылка на **папку** не подойдёт, нужна ссылка на каждый файл.

## Как точки сравниваются между играми
Точки с одинаковым названием в разных играх считаются одной и той же точкой (регистр и «ё/е» не важны). Если точка была «наша», а стала чужой, она автоматически помечается как **потерянная**, а в обратном случае как **взятая**. Отметку можно поставить и вручную в форме точки. При создании новой игры можно перенести точки из прошлой: названия совпадут, и сравнение заработает само.

## Замена подложки
1. Сохраните карту одним файлом PNG или JPG. GIF лучше не использовать: в нём всего 256 цветов.
2. Нарежьте её командой `python tools/make_tiles.py карта.png tiles --skip-top` (нужен `pip install pillow`).
3. Если новая картинка того же полигона с теми же границами, точки останутся на своих местах: координаты хранятся в долях ширины и высоты.

## Запасной вариант: онлайн-база Supabase
Если когда-нибудь захочется править игры на сайте без загрузки файла на GitHub, в сайте уже есть режим Supabase. Таблицы и правила доступа лежат в `supabase/schema.sql`, переключение делается строкой `storage: 'supabase'` в `js/config.js`. Хостинг при этом остаётся на GitHub Pages.

## Верхняя сцена (таймер и галереи)

- Таймер считает до **ближайшей игры** — той, что отмечена галочкой «Ближайшая игра», иначе до первой будущей по дате. Время начала задаётся в окне игры (поле «Начало»); если пусто — берётся `hero.startTime` из `js/config.js`.
- Плашка «Ближайшая игра» закреплена под шапкой при прокрутке (на ПК и телефоне). Отключить: `hero.pinBar: false`.
- Фото галерей меняются в админке: кнопка «▣ Верх сайта» или значок ✎ на самой галерее. Можно указать файл из папки сайта (`img/hero/...`) или ссылку Google Drive. Сохраняется в `games.json` — после правки скачайте его и залейте, как обычно. Пока в `games.json` галерей нет, берутся запасные из `hero.galleries` в `js/config.js`.
- Параллакс: `hero.parallax` (`strength: 0` — выключить).

## Вход для админа

Посетители значок замка не видят. Чтобы войти, откройте сайт с `?admin` в конце адреса (например `https://ЛОГИН.github.io/sadovka/?admin`) и введите пароль.
Сменить пароль: в админке «Ещё → Сменить пароль…» — она выдаст строку `adminPasswordHash: '…'`; вставьте её в `js/config.js` и залейте файл.
Важно: даже без пароля посторонний не может изменить сайт — правки в браузере видит только он сам. Опубликовать изменения может только тот, у кого есть доступ к вашему GitHub.

## Карта и колёсико мыши

Колёсико над картой прокручивает страницу. Масштаб карты — Ctrl + колёсико (на Mac — ⌘ или щипок на тачпаде), а также кнопки + и −.

## Если после обновления сайт выглядит по-старому

Браузер помнит старые файлы. В `index.html` у подключений стоит метка версии `?v=20261014d` — после правки JS или CSS поменяйте число (например, на сегодняшнюю дату), и браузеры загрузят свежие файлы.

## Общая база Supabase (несколько админов)

С базой правки сохраняются сразу для всех — скачивать и заливать `games.json` больше не нужно.

1. Supabase → **SQL Editor** → New query → вставьте весь `supabase/schema.sql` → **Run**.
2. **Authentication → Users → Add user**: email и пароль для каждого админа, галочка *Auto Confirm User*.
3. В SQL Editor: `insert into public.site_admins (email) values ('admin1@mail.ru'), ('admin2@mail.ru');`
4. **Authentication → Sign In / Providers → Email**: выключите *Allow new users to sign up*.
5. **Project Settings → API**: скопируйте *Project URL* и ключ *anon* (*publishable*) в `js/config.js` → `supabaseUrl` и `supabaseAnonKey`. Залейте `config.js` на GitHub.
6. Первый админ, который войдёт (`…/?admin`, email и пароль), автоматически перенесёт данные из `data/games.json` в базу.

Как это работает:
- посетители читают данные из базы; если база недоступна — из `data/games.json` (это запасная копия; её можно обновлять через «Ещё → Скачать копию»);
- если два админа правят одновременно, второй при сохранении получит предупреждение, сайт загрузит свежую версию, и правку нужно повторить — чужие изменения не затираются;
- телефоны игроков хранятся отдельно и видны только админам;
- свой пароль админ меняет в «Ещё → Сменить мой пароль…»; добавить или убрать админа — в таблице `site_admins` (SQL внизу `schema.sql`).
